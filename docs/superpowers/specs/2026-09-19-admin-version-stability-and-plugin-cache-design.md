# SVGA Editor 后台版本稳定与插件缓存优化设计

日期：2026-09-19

## 目标

本次改动同时解决以下问题：

1. 后台用户卡片中的 PRO 按钮与头像未垂直居中，按钮状态样式与插件端不一致。
2. 插件画布默认背景仍为纯黑色，而不是深色棋盘格。
3. 插件首次进入序列帧时仍可能等待后台会话或完整素材清单，打断操作。
4. 浏览器后台刷新后短暂或持续显示旧版素材管理，切换页面或标签后又恢复新版。
5. 插件完整包与 GitHub Pages 后台仓库中存在不同年代的后台源码，容易再次部署旧版本。

成功标准：后台刷新、切换页面和切换浏览器标签时始终保持同一套素材管理界面；插件点击序列帧后立即展示本地缓存；仅检测到素材 revision 变化或发生明确素材写操作时才获取完整清单。

## 已确认根因

### 后台版本回滚

- 插件完整包中的 `cache-bridge/admin/index.html` 是旧的单文件后台。
- GitHub Pages 仓库中的入口已改成模块化后台，但同时加载 `main-v2.mjs`、`official-materials-v6.mjs`、`official-materials-stable-v7.mjs`、`admin-upload-v7.mjs` 和 `admin-upload-queue-v8.mjs`。
- `main-v2.mjs` 会先渲染旧素材列表；v6 再通过 `MutationObserver` 异步覆盖；v7 和上传补丁继续拦截事件。用户看到的界面取决于模块加载、接口响应和 DOM 变更顺序。
- GitHub Pages 对 HTML 返回 `Cache-Control: max-age=600`，且现有查询参数版本号不能保证形成独立 CDN 缓存键，导致不同边缘节点可能短时间返回不同入口版本。

### 序列帧进入延迟

- 官方素材已有 revision + `clientStorage` 元数据缓存，但 UI 每个插件会话首次进入序列帧仍会初始化官方和个人素材流程。
- 个人素材列表在读取本地快照前会先建立远端个人库会话，因此即使本地已有完整元数据，也可能阻塞首次显示。
- 加载遮罩会把“缓存读取”和“远端同步”都表现为阻塞操作，造成用户认为每次进入都在重新同步。

## 设计

### 1. 后台采用唯一素材管理器

新增一个唯一的素材管理模块，吸收以下能力：

- 官方/用户素材 Tab；
- 标签筛选、新建、重命名和拖拽排序；
- 素材重命名、锁定、显示/隐藏和删除；
- 多文件夹上传、分类上传和上传队列；
- 动态预览按需加载及手动补齐；
- 操作成功后局部更新，避免整页列表重复重绘。

`main-v2.mjs` 只负责外壳、导航、登录、用户和反馈模块，不再渲染素材卡片。入口不再加载 v6/v7/v8 补丁模块，也不再依赖 `MutationObserver` 覆盖另一套 DOM。

素材管理模块对外只暴露一个初始化入口，并拥有自己的状态、请求序列和销毁逻辑。离开素材管理页面后，未完成请求可以结束，但不得重新写入当前页面。

### 2. 后台资源采用不可混用的发布版本

- 新发布资源使用包含构建号的真实文件名，不使用查询参数作为唯一版本边界。
- 入口 HTML 在一个发布中只引用同一构建号的 JS/CSS。
- 旧构建资源继续保留，确保缓存中的旧 HTML 仍可加载完整旧构建，而不是与新构建混用。
- 页面设置 `window.__SVGA_ADMIN_BUILD__`，用于线上验证和问题定位。
- CI 检查入口只存在一个素材管理模块、所有发布资源属于同一构建号、禁止重新引入旧补丁脚本。

GitHub Pages 的十分钟入口缓存仍可能让用户短时间看到完整旧构建，但不会再发生同一页面由旧布局变成新布局、刷新后回退又恢复的现象。

### 3. PRO 按钮

- 保持当前按钮尺寸：高度 30px、现有水平内边距不变。
- 按钮位于用户卡片第三列，顶部偏移 2px，使其中心线与 34px 头像中心线一致，而不是与整张用户卡片居中。
- 未开通状态使用插件端“开通 PRO”的紫色描边、紫色文字和淡紫背景。
- 已开通状态使用插件端金色描边、金色背景和扫光文字；继续显示“已开通PRO”。
- 动态更新权限后只更新当前按钮状态，不重新加载整张用户列表。

### 4. 插件画布默认背景

- 初始化状态从 `black` 改为 `checkered-dark`。
- 背景选择器默认激活深色棋盘格按钮。
- 已保存项目或用户主动选择的背景仍按原逻辑恢复，不覆盖已有偏好。

### 5. 序列帧本地优先

#### 官方素材

1. 点击序列帧 Tab 后先从 `clientStorage` 读取元数据，从 IndexedDB/缓存桥恢复动态预览并立即渲染。
2. 当前控制面会话继续返回轻量 `officialSequenceRevision`；该请求同时承担登录、PRO 权限和在线状态，不额外增加一次素材清单请求。
3. 本地 revision 与远端 revision 相同：不请求 `official-sequences`。
4. revision 不同：先显示缓存，再静默获取完整清单；仅新增或更新的预览进入下载流程。
5. 本地没有可用快照：执行首次完整同步，并显示现有进度层。

#### “我的”素材

1. 有可用本地元数据快照时，首次进入直接返回本地快照，不先建立远端个人库会话。
2. 本机上传、删除、重命名成功后立即更新本地快照，并把个人素材状态标记为需要核对。
3. 明确重试、本地无缓存、个人素材发生写操作或会话已报告 personal revision 变化时才请求远端清单。
4. 跨设备变化允许在下一次轻量会话核对后更新，但不得阻塞缓存内容显示。

#### 加载反馈

- 缓存恢复不显示模态遮罩。
- 静默 revision 更新只显示非阻塞状态文字。
- 只有首次无缓存、用户主动重试或新增素材缺少预览时显示进度层。

## 源码归属与发布

- GitHub Pages 后台以 `wenshiyun77/Figma-Svga` 的 `cache-bridge/admin` 为唯一线上源码。
- 插件源码以当前 v0.8.36 完整包为基线；GitHub Pages 仓库根目录中较旧的 `src/main.js`、`src/ui.html` 不作为插件发布源。
- 最终插件交付包包含与线上后台一致的 `cache-bridge/admin` 快照，防止后续从插件包手动部署时覆盖为旧后台。
- 后台改动提交并推送 `main`，等待 Pages 工作流完成后再做线上验证。

## 测试与验证

### 自动测试

- 入口只加载一个素材管理模块，无 v6/v7/v8 补丁脚本。
- 入口 JS/CSS 构建号一致，存在明确构建标识。
- 素材页一次渲染完成，无 MutationObserver 二次替换列表。
- PRO 两种状态样式、30px 尺寸及与头像中心线的 2px 偏移。
- 插件默认 `canvasBg` 为 `checkered-dark`，对应按钮默认激活。
- 官方 revision 相同不请求完整列表；revision 不同先返回缓存再更新。
- 个人素材有缓存时不先建立远端会话；写操作和主动重试会触发核对。
- 缓存命中时不显示阻塞加载层。

### 线上验证

- 连续普通刷新、强制刷新、打开新标签和切换浏览器标签，构建标识保持一致。
- 素材管理打开后不再出现旧布局到新布局的跳变。
- 检查入口与资源哈希，确保 Pages 已发布同一构建。
- 在已有序列帧缓存的 Figma 中关闭并重开插件，点击序列帧后立即显示卡片；服务端 revision 未变时无完整素材请求。
- 后台上传一套新素材后，插件控制面拿到新 revision；下次进入序列帧时先显示旧缓存，再静默加入新素材。

## 失败处理与回滚

- 新素材管理模块请求失败时保留当前已渲染内容，仅显示错误提示和重试按钮。
- revision 更新失败时继续使用本地缓存，不清空素材列表。
- Pages 新构建异常时，只需把入口恢复到上一构建文件名；上一构建资源必须保留。
- 插件包发布前保留原 v0.8.36 包作为可恢复版本，不覆盖唯一副本。
