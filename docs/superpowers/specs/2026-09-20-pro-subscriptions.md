# PRO 订阅（包月与永久）设计规格

## 目标

在不改变插件主要布局和既有 PRO 功能权限的前提下，支持后台为用户开通、续费和区分“包月PRO”与“永久PRO”。包月从首次开通起按 30 天计，到期自动失效；在最后三天提供明确的倒计时提示。

## 已确认的产品规则

- 后台每张用户卡片显示两个 30px 高按钮：`包月PRO`、`永久PRO`，放在头像区域的垂直中线位置。
- 两个未开通按钮均为灰色，文案固定为 `包月PRO`、`永久PRO`。
- 已开通的对应按钮为现有金色风格；扫光只作用于文字，不改变按钮背景或边框。
- 按钮不能再通过再次点击直接关闭权限。
- 点击未开通的包月按钮，打开小弹窗；数量控件固定为 `−  1  +`，最小为 1，确认后从当前时间起开通 `数量 × 30` 天。
- 点击已开通且未到期的包月按钮，打开相同弹窗；确认后从当前到期时间顺延 `数量 × 30` 天。误触关闭弹窗不写入数据。
- 点击已到期的包月按钮，确认后从当前时间起计算，不沿用过去的到期时间。
- 点击未开通的永久按钮，打开确认弹窗，确认后开通永久 PRO。已开通永久按钮只显示“已开通永久PRO”的状态提示，不提供关闭动作。
- 用户只有包月 PRO 时，插件标题栏显示 `包月PRO`；永久 PRO 时显示 `永久PRO`。
- 包月 PRO 用户点击插件标题栏的 `包月PRO`，仍打开现有未开通用户的购买/联系弹窗，便于再次下单；永久 PRO 保持现有“点击不弹窗”的行为。
- 包月在剩余时间不超过 72 小时时，插件标题栏显示时钟图标和向上取整后的剩余天数（3、2、1）。到期后不显示倒计时且不再有 PRO 权限。
- 后台用户数据的 PRO Tab 显示当前套餐、开通时间；包月还显示到期时间。历史的既有 `lighting=true` 用户迁移为永久 PRO，确保不丢失既有权限。
- 若用户同时存在包月和永久状态，永久 PRO 优先：插件显示 `永久PRO`，不显示倒计时。新模型中升级永久会替换当前包月权益状态。

## 数据模型与权限边界

新增私有表 `public.svga_plugin_pro_subscriptions`，每个 Figma 用户一条当前权益记录：

| 字段 | 含义 |
| --- | --- |
| `figma_user_id` | 主键，关联插件用户 |
| `plan_type` | `monthly` 或 `permanent` |
| `started_at` | 当前套餐的首次开通时间；包月续费时不改变 |
| `expires_at` | 包月到期时间；永久套餐为 `NULL` |
| `updated_at` / `updated_by` | 管理端最近一次权益操作的审计信息 |

表启用 RLS，撤销 `anon` 和 `authenticated` 的所有权限，仅允许 `service_role` 访问。客户端从不直接访问该表。

新增仅供 `service_role` 调用的 SQL 函数，在一个事务中锁定并更新订阅记录：

- `monthly`：若原记录为有效包月，则从原 `expires_at` 加 `30 × months` 天；否则从数据库 `now()` 加该时长。
- `permanent`：将套餐设为永久并清空到期时间。
- 操作成功后，同步 `svga_plugin_feature_permissions.lighting=true` 以兼容现有里程碑和旧逻辑；真正的有效 PRO 判断仍基于订阅记录和数据库当前时间。

后台 Edge Function 返回的权益结构统一为：

```ts
type ProSubscription = {
  plan: "none" | "monthly" | "permanent";
  startedAt: string | null;
  expiresAt: string | null;
  daysRemaining: number | null;
};
```

`features.lighting` 只有在 `plan === "permanent"` 或 `plan === "monthly" && expiresAt > now()` 时才为真。到期不依赖计划任务：每次 session、管理员用户列表和 PRO 筛选都在服务端按当前时间计算，因此无法出现缓存中的过期授权。

## 接口与界面

### 管理接口

保留动作名 `admin-user-feature` 的路由入口，但升级请求体为：

```json
{
  "figmaUserId": "…",
  "feature": "lighting",
  "plan": "monthly | permanent",
  "months": 1
}
```

该动作仅接受已认证管理员。旧的 `enabled` 布尔值不再由新版后台发送。

管理员用户列表为每一位用户返回 `subscription`，并将 PRO Tab/统计仅建立在有效权益之上。用户卡片显示本地化的套餐、开通时间和（包月）到期时间。

### 后台弹窗

用户卡片上的两个按钮使用自定义小弹窗，而不是浏览器 `confirm()`：

- 包月：标题、当前或新到期时间、`−  1  +`、取消、确认。
- 永久：清楚说明开通后长期有效，取消、确认。
- 请求期间禁用控件；成功后只更新当前卡片和弹窗，避免为了一个权益操作重新加载用户列表、打断管理员位置。

### 插件端

主线程把 `subscription` 连同现有 `features` 传给 UI；UI 继续以 `lightingUnlocked` 控制 PRO 功能。

- 标题栏只替换现有 PRO 文案，不改变尺寸和整体位置。
- 包月有效时显示 `包月PRO`；剩余 1–3 天时追加内联 SVG 时钟和 `剩余N天`。
- 包月标题栏按钮可打开既有 `开通 PRO` 联系弹窗；永久用户仍不打开。
- 网络不可用时沿用现有保守逻辑：不会因本次改动自行提升权限。

- 每项生产行为先写出失败的静态/运行时测试，再实现使其通过。

- 运行插件完整检查、管理员不可变发布检查、语法检查和压缩包完整性检查。
- 将 migration 应用于生产 Supabase、部署 `plugin-control` Edge Function、发布新的不可变管理员 release，并用线上响应验证套餐字段和到期判断。
